# Public contract changes

Canonical ISessions creation takes caller SessionId; IRequests submission takes caller RequestId separately from SubmitRequest payload. CQRS commands carry the same IDs and facades forward them unchanged. Empty and duplicate IDs reject before effects; no auto replacement. Caller recovery queries exact IDs and compares immutable context/submission fingerprint.

SessionRuntime exposes a typed targeted-dispatch command in HostControlled mode. Automatic scheduling and explicit target dispatch share the same atomic store policy; incorrect mode/target cannot fall back to another queued request. Mode persists in format2 and is checked before recovery/start. Controlled shutdown preserves queued input.

The framework package adds its own qualified typed outcome and invocation-context contracts using public AIAgent/AgentSession/AgentRunOptions APIs. Microsoft Agent Framework remains an unmodified external NuGet dependency. No internal framework access, fork or upstream patch is required.

Typed outcome admission validates declared state/certainty/output/continuation consistency and pending/background flags before serialization. Native session observation commits separately from stable framework session binding. Captured output and known termination are not erased by missing continuation.

## Typed outcome, invocation and evidence surface (T005)

- `FrameworkAgentOptions.QualifiedOutcomes` (default false) and `MaximumObservations` (default 16, nonnegative; 0 forbids agent-reported observations).
- `FrameworkExecutionOutcome`: recognized only as the exact CLR `AgentResponse.RawRepresentation` of a qualified registration. A typed NotStarted after an acknowledged operation or native session observation is Unknown.
- `FrameworkInvocation.TryGet(AgentRunOptions?)`: the adapter passes the context on its own run options as a typed member, not in `AdditionalProperties`. A clone of those options (`AgentRunOptions.Clone`) carries the same context. A context placed in `AdditionalProperties` is not recognised: this is a behavioural change from 0.2.0-alpha.8, where it was read from there. The reason is that a chat-client agent copies run-option additional properties into the chat options it sends, which made the context, with its SDK identities, reach chat clients and their serialized requests (`UnitTests/FrameworkChatClientIsolationTests`). It is a transient context with `ObserveOperationAcceptedAsync` (once per invocation), `ObserveNativeSessionAsync` (first value fixed) and `ReportProgressAsync`; identities are nonblank and at most `MaximumReferenceCharacters` (512). Callbacks are awaited, deadline-bound and refused after the invocation returned.
- `ProviderObservationKind.InvocationPrepared` and `NativeSessionObserved` are new members. Only the framework adapter emits InvocationPrepared; for other adapters `ExecutionEvidence.InvocationPrepared` is false by construction and means only "not recorded". Third-party `ISessionStore` implementations must persist or explicitly refuse these kinds; refusal makes framework dispatches fail before invocation.
- `RequestSnapshot.Evidence` (`ExecutionEvidence`): public store reads, lists and cancellation results project it from the stored dispatch envelope; it is null before dispatch reservation. Stored snapshot copies are refused. Store implementers must project it on every public request read.
- `SessionBlockReason.ProviderUnavailable` together with `SessionSnapshot.ConfigurationUnavailable` records persisted **state**, not a proven cause:
  - The completion pathway (`SessionBindingPolicy.AfterCompletion`) sets `ProviderUnavailable` when a confirmed end reports `ContinuationAvailable == false` or `ProviderSessionExpired`. It leaves `ConfigurationUnavailable` false and `AvailabilityError` null.
  - The configuration pathway (`SessionAvailabilityPolicy.ForConfiguration`, applied through `ISessionStore.CommitConfigurationAvailabilityAsync`) sets `ProviderUnavailable` together with `ConfigurationUnavailable == true` and an `AvailabilityError` when the registered provider is unavailable.
  - The public `ISessionStore.MarkSessionBlockedAsync(sessionId, ProviderUnavailable)` produces the same persisted shape as the completion pathway (`ProviderUnavailable`, `ConfigurationUnavailable == false`, no `AvailabilityError`) without any continuation being involved.
  - `ProviderUnavailable` with `ConfigurationUnavailable == false` therefore does not prove that a continuation was lost.
  - `ConfigurationUnavailable == true` identifies a block that the configuration check itself recorded. Only such a block is cleared by a later successful configuration check. Any other `ProviderUnavailable` stays until the session is closed. This revalidation eligibility is a rule about which block the check may clear, not a statement of why the block was originally set.
  - Framework sessions have no operation-aware recovery provider, so a block from the completion pathway is not cleared by recovery either. Pinned by `IntegrationTests/ProviderBlockProvenanceTests` and `UnitTests/SessionAvailabilityTests`.
  - Decision (T009, root choice C): no further block reason and no derived cause property; the persisted format is unchanged.
