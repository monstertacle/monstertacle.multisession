## Exact recovered-submission identity

Source checked at af13164: RequestSnapshot currently exposes no immutable payload identity. AcceptanceTransactions.Insert persists SubmissionJson and SnapshotJson in one transaction. SubmissionStoreConsistency.Assert validates frozen constraints before startup mutation but cannot detect replacement with a different valid input. RequestStoreConsistency separately validates request/row identity and times. QueryTransactions returns the stored snapshot; host recovery must not resend payload to compare it.

Decision: Common owns RequestSubmissionFingerprint.Compute and the public snapshot fingerprint. A versioned fixed-order JSON array encodes session GUID, exact input, timeout ticks, nullable workspace key and write intent; SHA256 lowercase hexadecimal identifies those exact immutable fields. Null/empty and Unicode representations stay distinct. Request ID is not a submission field. SQLite computes once at acceptance and compares against the persisted immutable submission during pre-recovery consistency checking. Snapshot copies preserve the field. The test store mirrors accepted snapshots only; it does not establish durable guarantees.

Tests before behavior: changes to every input field change the fingerprint; identical cloned input preserves it; receipt-loss/reopen returns the original fingerprint; changing a valid stored input or its fingerprint refuses before startup mutation. This is equality evidence, not cryptographic trust in a hostile writer who can rewrite both source and digest. No external SDK API or dependency changes are needed.

## Typed outcomes, invocation preparation and native observations (T005)

Source checked at 0597d9e. FrameworkExecution emitted OperationAccepted with the local dispatch ID before calling the agent, so durable intent was indistinguishable from an external receipt. Its AgentRunOptions were null, so an agent had no typed way to report a native session or operation and no awaited persistence before continuing. A response was success only through the narrow text contract; any known native failure, partial output or not-started fact became Unknown. A serialization failure after a confirmed end replaced the result with Failed and erased output (FrameworkFailureTests asserted that defect). DispatchObservationSink validated only SessionEstablished/OperationAccepted/Progress; ObservationTransactions persisted SessionReference and OperationReference into the StoredDispatch envelope; RequestSnapshot exposed no dispatch evidence after restart. DispatchTermination required an operation-aware reopen for every confirmed end without binding, including an explicitly unavailable continuation.

Decision (no new dependency, no external framework change):

- Common adds InvocationPrepared (reference must be the dispatch ID, once) and NativeSessionObserved (nonblank, first value fixed) observation kinds. The sink rejects duplicates and conflicts as provider misbehavior before storage. SQLite stores InvocationPrepared and NativeSessionReference in the existing StoredDispatch envelope, separately from SessionReference/binding. Public request reads project ExecutionEvidence from that single envelope; stored request snapshots never carry a copy and consistency refuses one.
- The framework package adds FrameworkInvocation, carried as an exact-CLR value in AgentRunOptions.AdditionalProperties. Its callbacks are awaited, linked to the dispatch deadline, bounded by FrameworkAgentOptions.MaximumObservations and refused after the invocation returned. Any failed, pending or late callback makes the turn Unknown; it cannot be overtaken by a successful response.
- FrameworkExecutionOutcome is recognized only as the exact CLR RawRepresentation and only for registrations with QualifiedOutcomes. Structural rules: success needs confirmed end, complete nonempty output and no error; failures need a matching defined error; NotStarted and Unknown carry no output; Unknown carries no continuation; background continuation tokens reject. Invalid or unqualified typed facts become Unknown, never text fallback. JSON/text lookalikes remain ordinary text.
- Confirmed end with failed or unavailable continuation keeps state and captured output, sets ContinuationAvailable=false without binding, and blocks the session through the existing SessionBindingPolicy. DispatchTermination does not demand an operation-aware reopen when continuation is explicitly unavailable.
- Generic post-invocation exceptions remain Unknown. No retry or resume is derived from any observation.
